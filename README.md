# 山雀企业项目工作台

**面向企业各类项目的轻量项目跟踪与协作工具。**

团队成员可围绕项目、关键节点和任务，集中呈现计划、实际进展与时间差距，帮助团队在日常跟踪和例会上掌握全局。

适用于科研、工程、固定资产投资、自研和预研等各类企业项目。

## 功能与特点

### 多项目总览

- 在同一张台账中查看项目与下级任务，默认展开，支持收起。
- 集中展示当前状态、任务完成情况、上一个与下一个关键节点、节点日期及最新进展。
- 按项目类型和项目状态筛选，快速定位需要关注的工作。

### 甘特图

- 在同一时间轴上展示项目周期、节点阶段与任务起止日期。
- 项目、节点和任务分层展示，可展开查看任务名称、执行人、日期与状态。
- 固定日期刻度，长周期项目横向滚动；支持拖动顶部日期栏，默认定位今天。
- 项目条显示节点达成比例，任务完成数量另行统计，便于区分阶段进展与日常工作量。

### 关键节点与滚动任务

- 项目支持多个负责人、多个节点；任务支持多个执行人以及独立的开始日和截止日。
- 每个节点最多指定一个节点任务，节点任务完成后自动达成节点；未设置时由有权限的人员手动确认。
- 强制达成节点时，关联的未完成任务同步完成。
- 任务支持未开始、进行中、受阻、已完成四种状态，可直接更新状态并填写说明。

### 团队协作

- 一个人可以加入多个团队，同一个项目也可以共享给多个团队。
- 共享项目使用同一份节点、任务与进展，避免重复维护。
- 快速切换团队，总览、甘特图和团队人员随之切换。
- “我的待办”跨团队汇总个人任务，同一任务只显示一次。
- 管理员统一维护用户账户，支持 Excel 导入、修改密码和设置系统管理员；团队主管从已有账户中添加团队成员。

### 轻量部署

- Python 后端、React 前端、SQLite 数据库，一个服务提供页面和业务接口。
- 浏览器访问，无需安装客户端；运行服务器无需常驻 Node.js 服务。
- 使用 SQLite WAL 和任务版本校验处理多人读写与过期页面提交。
- 深绿主题、紧凑表格和统一图标，优先呈现项目状态与进展。

## 角色与权限

| 身份 | 职责范围 |
| --- | --- |
| 系统管理员 | 维护用户账户、创建团队、设置团队角色、关联团队项目 |
| 团队总监 | 查看当前团队项目，掌握整体进展 |
| 团队主管 | 维护团队内项目、节点和任务，增减本团队普通成员 |
| 项目负责人 | 维护负责项目的进展和任务，分派工作；不能变更节点计划 |
| 任务执行人 | 更新获派任务的状态与完成情况 |

团队总监、团队主管和团队成员角色按团队设置，管理员可直接在角色列选择并保存；项目负责人按项目指定。同一人在不同团队和项目中可以承担不同职责。

## 技术栈

| 层次 | 当前实现 |
| --- | --- |
| 前端 | Ant Design Pro 6、React 19、Ant Design 6、Umi Max 4 |
| 后端 | Python、Flask 3、Waitress 3 |
| 数据库 | SQLite，启用 WAL 模式 |
| 账户导入 | Excel / openpyxl |

当前版本使用 SQLite，不需要单独安装数据库服务。

## 服务器部署

### 环境要求

- Windows 或 Linux 服务器。
- Python 3.11；Node.js 22 和 npm 用于安装前端依赖及构建。
- 服务器本地磁盘上的可写数据目录。
- 客户端使用现代浏览器，通过服务器地址访问。

以下命令均在仓库根目录执行。首次部署需要先安装依赖、构建前端，再启动服务。仓库不包含业务数据或预置密码，示例数据仅用于自动化测试。

### Linux

```sh
python3.11 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
npm ci
npm --prefix frontend ci
npm run frontend:build

.venv/bin/python run.py --server --port 5086 --data-dir /srv/shanque/data
```

提前创建 `/srv/shanque/data`，并赋予服务运行账号读写权限，也可替换为自己的绝对路径。

### Windows

在 PowerShell 中执行：

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
npm ci
npm --prefix frontend ci
npm run frontend:build

.\.venv\Scripts\python.exe run.py --server --port 5086 --data-dir D:\Shanque\data
```

确保服务运行账号对 `D:\Shanque\data` 有读写权限。

### 首次初始化

首次启动时，在交互终端按提示设置 `manager` 管理员密码。密码长度为 8 至 128 位，需要输入两次。

新数据库只初始化管理员和默认团队，不创建演示项目。随后：

1. 打开 `http://服务器IP:5086`，使用 `manager` 登录。
2. 在左下角用户菜单的“用户账户”中创建或导入人员。
3. 在左下角用户菜单的“团队管理”中建立团队、添加人员并设置团队角色。
4. 切换到相应团队，创建项目，设置类型、负责人、周期和节点，再按需分派任务。

### 启动参数

| 参数 | 说明 |
| --- | --- |
| `--server` | 启用多人服务模式；首次初始化时交互设置管理员密码 |
| `--port 5086` | 服务端口，源码运行默认 5086 |
| `--host 0.0.0.0` | 监听地址，服务器模式默认监听所有 IPv4 网卡 |
| `--data-dir <路径>` | 数据目录，建议使用固定绝对路径；默认是仓库下的 `instance/server` |

每个数据目录运行一个服务进程。Waitress 在服务器模式使用 8 个请求线程。多人可以同时查询，数据库写入依次提交；任务被他人修改后，旧页面提交会提示冲突，刷新核对后可重新操作。

### 常驻服务与访问入口

首次交互初始化完成后，将上述启动命令配置为操作系统服务：Linux 可用 systemd，Windows 可用服务管理工具。固定工作目录、Python 虚拟环境路径、运行账号和数据目录，并配置自动启动与日志保存。

内网直连时，按访问范围开放服务端口。通过 HTTPS 反向代理访问时，可让应用只监听本机地址：

```sh
.venv/bin/python run.py --server --host 127.0.0.1 --port 5086 --data-dir /srv/shanque/data
```

由反向代理统一转发页面、`/api/`、`/assets/` 和 `/static/` 等所有路径到该服务。前端构建产物由 Python 直接提供，不需要另外启动前端开发服务器。

## 数据维护与升级

数据目录包含：

| 文件 | 用途 |
| --- | --- |
| `workspace.sqlite3` | 用户、团队、项目、节点和任务数据 |
| `local.key` | 会话签名密钥 |
| SQLite 日志文件（如存在） | WAL 等数据库运行文件 |

### 备份与恢复

停止服务后，复制整个数据目录保存备份。恢复时停止服务，将完整备份放入目标目录，再用相同的 `--data-dir` 启动。

### 版本升级

1. 停止服务，备份整个数据目录。
2. 更新源码，安装依赖并重新构建前端。
3. 使用原数据目录启动服务，程序会执行已有的数据库结构升级逻辑。
4. 登录核对团队、项目、节点与任务。

如需回退，应配套恢复升级前的源码和数据备份。迁移到另一台服务器时，同样复制完整数据目录，并保持服务账号可读写。

业务数据、密钥、依赖目录和构建产物均不应提交到源码仓库。对外发布时使用源码及构建流程，不附带实际企业台账。

## 开发与验证

安装依赖和构建方法见上方部署步骤。前端代码、页面接口和开发说明见 [前端文档](frontend/README.md)。

```sh
# 前端规范与类型检查
npm run frontend:check

# 构建生产页面
npm run frontend:build

# 后端业务测试（Linux）
.venv/bin/python -m unittest discover -s tests -v
```

Windows 测试命令：

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

测试使用独立临时数据库。浏览器业务验证脚本为 `scripts/verify_pro_ui.py`，需要额外安装 Playwright 并准备 Chrome；它会启动临时数据库和随机端口，不写入正式业务数据。

### 目录结构

```text
frontend/          前端页面、组件、主题和构建配置
workspace/         Python 业务、权限、数据模型和页面接口
tests/             业务与接口测试
scripts/           前端构建及浏览器验证脚本
run.py             服务启动入口
requirements.txt   Python 依赖
```
